# 위하고 수신결재 → 이체관리 시트 자동 입력

사무실 PC에서 브라우저가 위하고 수신결재함을 열어 결의서 내용을 읽고, `[부동산]이체관리_자동문구` 시트의 이번 달 탭(`11월 이체` 등)에 한 줄씩 넣습니다. 규칙은 「수신결재 건 → 이체관리 시트 입력 가이드」를 따릅니다.

```
[사무실 PC] sync.js ──(위하고 화면 읽기)──▶ [Apps Script 웹앱] ──▶ 시트 이번 달 탭
```

## 자동으로 하는 것

| 칸 | 넣는 값 |
|---|---|
| 지급여부 | 비워 둠 |
| 날짜 | 입력한 날 |
| 해당부동산 / 통장 | `위하고_매핑` 시트에 적어 둔 키워드가 제목·기안부서에 있을 때만 입력. 드롭다운 목록에 없는 값이면 빈칸 |
| 받는사람 | 결의서의 예금주 |
| 금액 | 숫자. 제목 금액과 본문 금액이 다르면 넣지 않음 |
| 내용 | 제목에서 `26/11/19_`와 `_금액`을 뺀 부분 |
| 지급수단 | 계좌이체 |
| 증빙유형 | 결의서에 `증빙유형` 항목이 있고 그 값이 목록에 있을 때만 |
| 증빙수취 | 수신결재함에 있으면 `필요`. 나중에 결재내역함으로 넘어가면 `완료`로 바꿈 |
| 지출결의서 | 결재 |
| 비고 | `위하고 수신결재 / 요청일 11/19` + 확인이 필요한 이유 |
| 은행 / 계좌 | 결의서 값. 숫자만 있는 계좌는 4자리씩 띄움 |

이런 건은 시트에 넣지 않고 `위하고_처리기록` 시트에 이유를 남깁니다.
- **중복의심**: 이번 달 탭에 받는사람과 금액이 같은 행이 이미 있음
- **수동확인**: 받는사람이나 금액을 확실히 읽지 못함

한 번 처리한 문서는 다시 처리하지 않습니다. 다시 돌리려면 `위하고_처리기록`에서 그 줄을 지우세요.

## 설치 (처음 한 번)

### 1. Apps Script 웹앱 만들기
1. https://script.google.com 에서 **새 프로젝트**를 만듭니다. 시트에 이미 붙어 있는 스크립트에 넣으면 기존 웹앱과 충돌하므로 따로 만듭니다.
2. `apps-script/Code.gs` 내용을 통째로 붙여넣습니다.
3. 프로젝트 설정 → 스크립트 속성에 두 개를 추가합니다.
   - `SPREADSHEET_ID` = `1kUKbSUju8N5AhBM_JonOijMXnuj-A9JBSa2WIoqfNZA`
   - `SYNC_TOKEN` = 길고 아무도 모르는 문자열
4. 편집기에서 `setup` 함수를 한 번 실행하고 권한을 승인합니다. 시트에 `위하고_처리기록`, `위하고_매핑` 탭이 생깁니다.
5. 배포 → 새 배포 → 유형 **웹 앱**, 실행 계정 **나**, 액세스 **모든 사용자**로 배포하고 `/exec`로 끝나는 주소를 복사합니다. 토큰이 없으면 아무것도 하지 않습니다.

### 2. `위하고_매핑` 채우기
| 키워드 | 해당부동산 | 통장 |
|---|---|---|
| 양산 | 스테이레브소유 양산점 | 옆커폰본사통장 |

양산 줄은 `setup` 실행 때 자동으로 들어갑니다(당분간 본사통장에서 출금). 출금 통장이 바뀌면 이 줄의 통장만 고치면 됩니다.

해당부동산과 통장은 드롭다운 목록에 있는 글자와 **정확히 같아야** 들어갑니다. 비워 두면 그 칸은 빈칸으로 들어갑니다.

### 3. 사무실 PC 준비 (Windows)
1. https://nodejs.org 에서 Node.js LTS를 설치합니다.
2. 이 `wehago-sync` 폴더를 PC로 복사한 뒤, 폴더에서 PowerShell을 열고 아래를 실행합니다.
   ```
   npm install
   npx playwright install chromium
   copy config.example.json config.json
   ```
3. `config.json`을 메모장으로 열고 채웁니다.
   - `webAppUrl`, `token`: 1단계 값
   - `inboxUrl`: 위하고에서 **수신결재함**을 연 상태의 주소창 주소
   - `doneUrl`: **결재내역함** 주소창 주소
4. `npm run login`을 실행합니다. 브라우저가 뜨면 직접 로그인하고(2단계 인증 포함) 창을 닫습니다. 비밀번호는 저장하지 않고 로그인 상태만 `wehago-profile` 폴더에 남습니다.

### 4. 화면 구조 맞추기 (중요)
위하고 화면 구조는 실제로 열어 보지 않고 짐작으로 기본값을 넣어 두었습니다. 반드시 한 번 확인해야 합니다.
```
npm run inspect
```
- `목록 행 ... 찾은 행: 0개`라고 나오면 `config.json`의 `selectors.listRow`를 고쳐야 합니다. `debug/1-목록.html`과 스크린샷을 보고 맞춥니다.
- 마지막에 나오는 `첫 문서에서 뽑은 값`의 예금주, 금액, 계좌가 맞는지 확인합니다.
- `debug/` 폴더에는 계좌와 금액이 들어 있습니다. 다른 사람에게 보낼 때는 가려서 보내세요.

### 5. 미리보기 → 실제 입력
```
npm run preview
```
시트에 쓰지 않고 어느 탭 몇 행에 무엇이 들어갈지만 보여 줍니다. 맞으면 아래를 실행합니다.
```
npm run apply
```

### 6. 자동 실행 (작업 스케줄러)
작업 스케줄러 → 기본 작업 만들기 → 매일, 반복 간격 1시간 →
- 프로그램: `C:\Program Files\nodejs\node.exe`
- 인수: `sync.js run --apply`
- 시작 위치: `wehago-sync` 폴더 경로

종료 코드 2는 로그인이 풀렸다는 뜻입니다. `npm run login`을 다시 하세요.

## 알아 둘 점
- 위하고는 공개 API가 확인되지 않아 화면을 읽는 방식입니다. 위하고 화면이 바뀌면 4단계를 다시 해야 합니다.
- 자동 로그인 사용이 회사·위하고 이용 정책에 맞는지 확인하고 쓰세요.
- 다음 달 탭(예: `12월 이체`)이 없으면 입력하지 않고 오류로 알려 줍니다. 탭은 사람이 만듭니다.
- 은행명은 결의서에 적힌 그대로 넣습니다(`기업은행`과 `기업`을 맞추지 않음).
- 파서 테스트: `npm test`

## 대시보드에서 처리 현황 보기 (`/wehago.html`)
사이트의 `/wehago.html`에서 이번 달 결재 건수·미송금·증빙 미수취, 사람이 확인할 건, 최근 처리 기록, 마지막 자동 실행 상태를 봅니다. 계좌번호는 화면으로 보내지 않습니다.

Cloudflare Pages → 설정 → 환경변수에 세 개를 넣고 다시 배포합니다.

| 이름 | 값 |
|---|---|
| `DASHBOARD_KEY` | 대시보드 접근 키 (유입 분석 대시보드와 같은 값). **없으면 이 화면은 데이터를 보여주지 않습니다** |
| `WEHAGO_WEBAPP_URL` | Apps Script 웹앱 `/exec` 주소 |
| `WEHAGO_SYNC_TOKEN` | 스크립트 속성 `SYNC_TOKEN`과 같은 값 |

화면 오른쪽 위 **[접근 키]**에 `DASHBOARD_KEY` 값을 한 번 넣으면 그 브라우저에서는 계속 열립니다.
Apps Script 코드를 바꿨다면 배포 → 배포 관리 → 수정 → **새 버전**으로 다시 배포해야 반영됩니다.
