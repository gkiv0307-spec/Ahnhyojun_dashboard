# 공공데이터포털 오픈API 연동

법원경매 물건을 **시세·공매 자료와 대조**하기 위한 data.go.kr 오픈API 연동 설정입니다.

## 사용하는 API

| 용도 | 제공기관 | 데이터셋 ID | 엔드포인트 |
|---|---|---|---|
| 아파트 매매 실거래가 | 국토교통부 | 15126469 | `https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade` |
| 온비드 부동산 물건목록 | 한국자산관리공사 | 15157207 | `https://apis.data.go.kr/B010003/OnbidRlstListSrvc2` |
| 온비드 부동산 물건상세 | 한국자산관리공사 | 15157247 | `https://apis.data.go.kr/B010003/OnbidRlstDtlSrvc2` |

**세 API 모두 인증키가 같습니다.** `DATA_GO_KR_KEY` 하나만 등록하면 됩니다.

## 환경변수 등록

Claude Code 환경 설정(Environments → Environment variables)에 아래를 넣습니다.
로컬에서 쓸 때는 `.env.example`을 `.env`로 복사해 채웁니다(`.env`는 커밋되지 않습니다).

| Name | Value |
|---|---|
| `DATA_GO_KR_KEY` | 발급받은 **Encoding** 인증키 (`%2B`, `%3D` 포함된 형태) |
| `RTMS_APT_TRADE_URL` | `https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade` |
| `ONBID_LIST_URL` | `https://apis.data.go.kr/B010003/OnbidRlstListSrvc2` |
| `ONBID_DETAIL_URL` | `https://apis.data.go.kr/B010003/OnbidRlstDtlSrvc2` |

URL 3개는 스크립트에 기본값으로 들어 있어 **선택 사항**입니다. 엔드포인트가 바뀔 때만 덮어쓰면 됩니다.
인증키가 환경변수에 없으면 `~/.secrets/datagokr` 파일을 대신 읽습니다.

## 주의사항

- **반드시 `https`.** `http`는 이 실행 환경의 egress 허용목록에 없어 403이 납니다.
- **인증키를 재인코딩하지 마세요.** Encoding 키는 이미 퍼센트 인코딩된 상태라 `--data-urlencode`로 다시 감싸면 인증이 깨집니다. 스크립트는 쿼리스트링을 직접 조립합니다.
- 키 발급 직후엔 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 날 수 있습니다. 활성화까지 보통 1~2시간 걸립니다.
- 개발계정은 일일 호출 한도가 있습니다(보통 1,000~10,000건). 초과하면 `LIMITED_NUMBER_OF_SERVICE_REQUESTS` 오류가 납니다.
- **인증키를 커밋하지 마세요.** `.env`와 `.secrets/`는 `.gitignore`에 있습니다.

## CODEF — 대법원 법원경매정보 경매사건검색

**주의: data.go.kr이 아닙니다.** CODEF(codef.io)가 대법원 법원경매정보를 중계하는
**상용 API**로, 별도 계정과 자격증명이 필요합니다. data.go.kr 인증키는 여기서 쓰이지 않습니다.

| 항목 | 값 |
|---|---|
| **데모 (기본값)** | `https://development.codef.io/v1/kr/public/ck/auction-events/search` |
| 정식 | `https://api.codef.io/v1/kr/public/ck/auction-events/search` |
| 토큰 | `https://oauth.codef.io/oauth/token` (Basic 인증) |
| 인증 | `client_id:client_secret` → access_token → `Bearer` |

### 환경변수

| Name | Value |
|---|---|
| `CODEF_CLIENT_ID` | CODEF 클라이언트 ID |
| `CODEF_CLIENT_SECRET` | CODEF 클라이언트 시크릿 |
| `CODEF_API_BASE` | `https://development.codef.io` (데모, 기본값) → 검증 후 `https://api.codef.io` (정식) |

없으면 `~/.secrets/codef` 파일에 `client_id:client_secret` 한 줄로 저장해도 됩니다.

### 데모 → 정식 순서

정식은 호출당 과금이므로 **데모에서 먼저 검증하고 넘깁니다.**

```bash
codef_env       # 지금 어느 환경인지 확인 (기본은 데모)
codef_verify    # 데모에서 한 건 호출해 토큰 발급·응답 파싱까지 확인
```

`codef_verify` 가 통과하면 그때 환경변수에 아래를 넣어 정식으로 넘깁니다.

```
CODEF_API_BASE=https://api.codef.io
```

안전장치 세 가지를 넣어 두었습니다.

- **데모 호출은 주간 예산 카운터를 올리지 않습니다.** 과금이 없으므로 몇 번을 시험해도 정식 한도가 줄지 않습니다.
- **정식 환경에서 `codef_verify` 를 실행하면 거부합니다.** 검증은 데모에서 하라고 안내하고 종료합니다.
- **검증 전에는 정식 호출 자체가 막힙니다.** `codef_verify` 가 통과하면 `~/.secrets/codef_verified`
  에 시각이 기록되고, 이 표식이 없으면 정식 환경의 `codef_auction` 은 exit 3 으로 거부합니다.
  프롬프트 지시가 아니라 코드가 막으므로 자동 실행에서도 지켜집니다.

```bash
codef_env
# 환경: 데모 (development.codef.io) — 과금 없음, 예산 카운터도 올라가지 않음
# 데모 검증: 미완료 — codef_verify 를 먼저 실행하십시오
```

`codef_is_verified` 로 표식 여부만 따로 확인할 수도 있습니다.

### 사용법

```bash
codef_auction 대구지방법원 2025 8313          # 원본 JSON
codef_auction_summary 대구지방법원 2025 8313  # 물건내역 + 기일내역(유찰 사다리)
```

요청은 `organization` 고정값 `0004` + 법원명 + 사건 년도 + 사건번호입니다.
**법원명은 CODEF가 정한 표기를 그대로** 써야 합니다(`대구지방법원`, `서울중앙지방법원` 등).

### 받아오는 것

경매 판단에 필요한 항목이 그대로 들어옵니다.

- `resDateList` — **기일내역**: 기일, 종류(매각기일/매각결정기일), **최저매각가격**, **기일결과(유찰/낙찰)**
- `resProductList` — **물건내역**: **감정평가액**, **최저매각가격**, 물건용도, 물건상태, 최근입찰결과, 소재지
- `resInvolvedPersonList` — 당사자(채권자·임차인 등)
- `resClaimAmt` / `resFinalResult` / `resNote` — 청구금액 / 종국결과 / 담당계

지금까지 네이버 색인으로 간접 수집하던 유찰 이력을 **원천에서 직접** 받게 됩니다.

### 호출 한도 — 두 가지를 따로 셉니다

| 한도 | 기본값 | 적용 | 넘으면 |
|---|---|---|---|
| **일일** `CODEF_MAX_DAILY` | 100건 | 데모·정식 모두 | `codef_auction` 이 exit 4 로 거부 |
| **주간** `CODEF_MAX_CALLS` | 15건 | 정식만 (과금 대비) | exit 3 으로 거부 |

```bash
codef_daily_status    # 오늘(2026-08-25) CODEF 호출: 100/100건  (남음 0)
codef_daily_reset     # 오늘 카운터 초기화
```

일일 한도는 **CODEF 계정 자체의 제약**입니다. 넘기면 서버가 `CF-00012` 를 돌려주는데,
**그 실패 응답도 호출 1건으로 소모됩니다.** 그래서 스스로 세어서 미리 멈추고,
서버가 `CF-00012` 를 보내오면 그 즉시 오늘치를 소진 처리해 남은 호출을 낭비하지 않습니다.

날짜가 바뀌면 자동으로 0이 됩니다.

### 조회 우선순위

한도가 있으므로 관심 지역부터 채웁니다. 기본값은 **대구권 우선**입니다.

```bash
CODEF_PRIORITY_COURTS="대구지방법원 대구서부지원 경주지원 김천지원 상주지원 안동지원 영덕지원 의성지원 포항지원"

printf '서울중앙지방법원|2025|101016\n대구지방법원|2025|8197\n' | codef_prioritize
# 대구지방법원|2025|8197
# 서울중앙지방법원|2025|101016
```

`법원|년도|번호` 형식의 목록을 받아 우선순위 순으로 정렬합니다.
같은 순위끼리는 입력 순서를 유지합니다.

### 호출 예산 (유료 API)

CODEF는 호출당 과금이 있을 수 있어 **주 단위 호출 상한**을 스크립트에 넣었습니다.

```bash
codef_budget_status    # 이번 주(2026-W35) CODEF 호출: 3/15회  (남음 12)
codef_budget_reset     # 카운터 강제 초기화
```

- 기본 상한은 **주 15회** (`CODEF_MAX_CALLS`로 조절). **정식 엔드포인트는 호출당 과금이 발생하므로 이 가드가 실제로 비용을 막습니다.**
- ISO 주차가 바뀌면 카운터는 자동으로 0이 됩니다.
- 상한을 넘으면 `codef_auction`이 호출하지 않고 exit 2로 거부합니다. 토큰 발급 전에 막으므로 과금이 발생하지 않습니다.

자동 갱신 Routine은 **월요일 실행분에서만** CODEF를 호출하며, 우선순위 순으로 최대 15건만 검증합니다.

1. 7일 내 매각기일 임박 물건
2. 특수물건 의심 (실거래 시세 대비 최저가 20% 미만, 또는 유찰 6회 이상)
3. 감정가 과대평가 의심 (실거래 시세의 110% 초과)
4. 남으면 신규 등장 물건

나머지 요일은 네이버 색인 + 국토교통부 실거래가(둘 다 무료)만 씁니다.

### 참고

- 응답이 URL 인코딩된 JSON으로 오는 경우가 있어 스크립트가 두 경우를 모두 처리합니다.
- 타임아웃 300초 기준 API이므로 스크립트는 120초까지 기다립니다.
- 토큰은 `~/.secrets/codef_token`에 1시간 캐시됩니다.

## 물건 데이터 모델

[guriguri/cauca](https://github.com/guriguri/cauca) 의 스키마를 참고했습니다. 그 프로젝트의 크롤러 자체는
2014년 courtauction.go.kr 의 `.laf` 엔드포인트를 대상으로 해서 지금은 동작하지 않지만(404),
데이터 모델은 그대로 쓸 만합니다.

### 복합 유니크 키

```
(법원, 사건번호, 물건번호)
```

한 사건에 물건이 여러 개 붙는 경우가 흔합니다(`2024타경105734 [9]`, `[11]`).
사건번호만 키로 쓰면 이들이 뭉개지므로 **물건번호를 별도 필드로 분리**합니다.
CODEF 원본 검증에서도 이 키가 물건 단위 매칭 기준이 됩니다.

| 필드 | 내용 |
|---|---|
| `ct` | 법원명 |
| `caNo` | 사건번호 (물건번호 제외) |
| `ino` | 물건번호 (기본 1) |
| `multi` | 원본에 `[n]` 이 명시돼 있었는지 |

### 주소 분해

| 필드 | 내용 |
|---|---|
| `a` | 원본 주소 전체 |
| `a1` | 시군구 (`수성구`, `성남시 분당구`) |
| `a2` | 읍면동 (`만촌동`, `화원읍`, `수성동1가`) |

시군구 단위 필터에 씁니다. `scripts/parse_auction.py` 에 파서가 있습니다.

```bash
python3 -c "
import sys; sys.path.insert(0,'scripts')
from parse_auction import split_case, split_addr, uid
print(split_case('2024타경105734 [9]'))   # ('2024타경105734', 9, True)
print(split_addr('성남시 분당구 금곡동'))    # ('성남시 분당구', '금곡동')
print(uid('대구지방법원','2025타경8313',1)) # 대구지방법원|2025타경8313|1
"
```

주의할 점 두 가지:

- 법정동의 `~가` 는 **숫자를 동반**합니다(`수성동1가`). 이 조건이 없으면 `(상가)` 같은 괄호 주석을 읍면동으로 오인합니다.
- `성남시 분당구` / `수원시 권선구` 처럼 시와 구가 함께 오면 붙여서 한 단위로 다룹니다.

### 용도 표준 분류

courtauction.go.kr 검색폼의 3단 코드 체계를 따릅니다. `scripts/auction_taxonomy.py`.

| 단계 | 코드 | 값 |
|---|---|---|
| 대분류 `lclsUtilCd` | `0000802` | 건물 |
| 중분류 `mclsUtilCd` | `000080201` | 주거용건물 |
| 소분류 `sclsUtilCd` | `00008020101`~`11` | 단독주택 · 다가구주택 · 다중주택 · 아파트 · 연립주택 · 다세대주택 · 기숙사 · 빌라 · 상가주택 · 오피스텔 · 주상복합 |

```python
from auction_taxonomy import classify
classify("광주시 초월읍 도평리 139-38 (단독주택)")   # ('단독주택', '주거용건물', False)
classify("수성구 만촌동 1429 메트로팔레스 307동")    # ('아파트', '주거용건물', True)
```

세 번째 값은 **추정 여부**입니다. 소재지·비고에 용도가 드러나면 `False`,
아무 단서가 없으면 `아파트` 로 기본 처리하고 `True` 를 줍니다.
아파트 검색으로 모은 표본이라 기본값이 아파트이지만, **확정된 값과 반드시 구분해야 합니다.**
화면에서는 추정인 건 `?` 가 붙습니다.

### 특수권리 (아직 비어 있음)

지분매각 · 유치권 · 법정지상권 · 분묘기지권 · 별도등기 · 재매각 · 특별매각조건 ·
농지취득 · 예고등기 · 선순위 · 우선매수신고 · 맹지.

이 값들은 **원본 물건의 비고란**에 있습니다. 지금 수집 경로(네이버 색인)에는 비고 필드가
없어 `sp` 필드가 전부 비어 있습니다. CODEF 의 `resNote` / `resDetailList[].resNote`
가 들어오면 `auction_taxonomy.special_rights()` 로 뽑아 채웁니다.

**가격으로 추정한 "특수물건 의심" 과 혼동하지 마십시오.** 전자는 등기·공고에 적힌 사실이고
후자는 최저가율이 비정상적으로 낮다는 관찰일 뿐입니다.

### 물건 상태와 화면 처리

| `st` | 뜻 | 화면 |
|---|---|---|
| `진행중` | 입찰 가능 | 보통 |
| `매각` / `낙찰` | 낙찰자 확정 | **흐리게** + "매각 완료 — 입찰 종료된 물건입니다" |
| `종료` | 사건 종료 | **흐리게** + "사건 종료 — 입찰할 수 없습니다" |
| `연기` | 기일 연기 | 보통 |

입찰할 수 없는 물건이 눈에 띄면 안 되므로 `.card.closed` 로 흐리게 처리하고(불투명도 0.48),
정렬에서도 뒤로 밉니다. 마우스를 올리거나 키보드 포커스가 들어가면 원래 대비로 돌아옵니다.
"매각·종료 숨기기" 체크박스로 아예 걸러낼 수도 있습니다.

상태값의 1차 출처는 네이버 색인이라 시차가 있습니다. **CODEF 검증(월요일)에서
`resProductList[].resState` / `resDateList` 의 기일결과를 읽어 확정**하며, 이때 `verified:true` 가 붙습니다.

## 미해결

온비드 두 API는 **인증은 통과하지만 필수 요청변수 이름이 확정되지 않았습니다.**
파라미터 없이 호출하면 `NO_MANDATORY_REQUEST_PARAMETERS_ERROR`가 납니다.
후보(`DPSL_MTD_CD`, `PBCT_BEGN_DTM`, `CTGR_HIRK_ID`, `SIDO`, camelCase 변형 등)를 시도했으나 모두 같은 오류였고,
공식 활용가이드 문서는 data.go.kr 로그인 세션이 있어야 받을 수 있습니다.

data.go.kr에 로그인한 상태에서 각 API 페이지의 **상세기능 → 요청변수** 표를 확인해
`onbid_list` / `onbid_detail` 호출부에 반영하면 바로 동작합니다.

### 1. `resProductList[].resDetailList` 는 그 물건의 구성요소가 아니다

**사건 전체 목록을 물건마다 통째로 복사해 둔 것**이다.

호실이 붙는다.

**물건별 소재지는 `resInventoryList` 를 `resNumber` 로 맞춰야** 나온다.

```
resProductList[0].resNumber = 1   → resInventoryList 중 resNumber=1 → 6층601호
resProductList[3].resNumber = 4   → resInventoryList 중 resNumber=4 → 7층701호
```

### 2. `resDateList` 도 사건 전체 기일이 한 배열에 섞여 있다

`resNumber` 로 거르지 않으면 4개 물건 × 2회 유찰이 **"8회 유찰"** 로 합산된다.
2025타경31397 은 물건별 5회인데 합산하면 15회가 됐다.

### 3. 일괄매각 중복은 **주소까지 같을 때만** 접는다

2026타경3229 는 물건1=토지, 물건2=건물이고 감정가·최저가·주소가 전부 같다.

반면 3375 의 물건1·물건4 는 감정가가 4.91억으로 같지만 호실이 다르다
(601호 / 701호). 금액만 보고 접으면 물건 하나가 사라진다.

### `resAmount` 가 비어 오는 사건이 흔하다

2026-08-26 검증한 22개 물건 중 7개가 `resProductList[].resAmount` 가 빈 문자열이었다.

캘린더 격자가 한 줄로 흘러내린 채 발행됐다. 원인은 단순하다 —
`.cal-head` · `.cal-grid` · `.day` · `.dn` · `.cnt` · `.dg` 규칙이
**`site-template.html` 에 애초에 들어간 적이 없었다.**
캘린더 작업을 스크래치패드의 `auction-board.html` 을 직접 고쳐서 했고,

스타일이 통째로 증발했다.

**검증기는 이걸 잡지 못했다.** pageerror 0, 가로 스크롤 없음, 텍스트 길이
충분 — 전부 통과였다. 스타일이 없어도 DOM 은 멀쩡하기 때문이다.

그래서 발행 전 검사에 항목을 하나 더 넣는다:

```
site-pages.js 가 쓰는 class 이름 중 site-template.html 의 <style> 에
규칙이 없는 것을 전부 나열한다.
```

데이터 값(`진행중`·`매각`·`신건`)과 `data-*` 값(`list`·`m2`·`py`),
인라인 style 로만 꾸미는 것(`hero-home`)은 오탐이므로 걸러낸다.

### 격자는 두 번 다 같은 이유로 깨졌다

`.map-grid` 때와 똑같이 **격자 항목의 기본값이 `min-width:auto`** 라
글자 폭 아래로 못 줄어든다. `repeat(7,minmax(0,1fr))` + 항목에 `min-width:0`
이 없으면 390px 에서 7칸이 가로로 넘친다. 새 격자를 만들 때마다 확인한다.

모바일에서 `대구 1` 배지가 `대…` 로 잘려 건수를 잃는 문제도 있었다.
셀 좌우 여백을 3px→2px, 배지 여백을 4px→2px 로 줄여 숫자를 살렸다.

## 검증한 물건에 '미대조' 메모가 남아 있었다

`법원 확인` 배지와 `경매알리미 색인 기준 — 법원 원본 미대조` 문구가 같은

## 물건 상세 화면 (2026-08-26)

### 인증키가 서비스마다 다르다

### 법정동코드는 API 로 역탐색한다

건축물대장은 `sigunguCd`(5) + `bjdongCd`(5) 를 받는다.
법정동코드 전체자료는 code.go.kr 로그인이나 별도 활용신청이 필요한데,
**건축물대장이 `sigunguCd + bjdongCd` 만으로도 조회되고 응답 `platPlc` 에
주소가 들어 있어** 코드를 넣어 보고 돌아온 주소를 읽으면 표가 만들어진다.
`scripts/bjdong_discover.py` 가 이걸 한다. 결과는 `data/bjdong.json` (417개).

코드 뒤 5자리 = **읍면동(3) + 리(2)**.

| 지역 | 대역 | 비고 |
|---|---|---|
| 동 | `101xx` ~ `1xxxx` | 리 자리는 `00` |
| 읍 | `25x` ~ `26x` | 리가 따로 있어 뒤 2자리를 훑어야 한다 |
| 면 | `31x` ~ `33x` | 위와 같음 |

실측 접두 — 달성군: 화원읍 250 · 논공읍 253 · 다사읍 256 · 유가읍 259 ·
옥포읍 262 · 현풍읍 265 · 가창면 310 · 하빈면 330.

칠곡군: 왜관읍 250 · 북삼읍 253 · 석적읍 256 · 동명면 320.

**리 코드는 `00`·`01` 이 아니라 `21`·`31` 부터 시작하는 곳이 많다.**
접두를 찾을 때 `xxx00` 만 훑으면 대부분 놓친다.

미발견: 달성군 구지면 · 칠곡군 약목면 · 경주시 천북면 (해당 물건 4건).

## 온비드 공매 — 필수 요청변수를 찾았다 (2026-08-26)

| 0004 | 불용품 | 9 |
| 0005 | 기타일반재산 | 13,742 |
| 0007 | **압류재산** | 55,265 |
| 0010 | 국유재산 | 3,427 |

`pvctTrgtYn`(수의계약 대상 여부)은 **Y/N 이 서로 다른 집합**이라 둘 다 받아야 한다.

### 먹는 필터 / 안 먹는 필터

실측으로 갈랐다. 안 먹는 것은 오류 없이 **조용히 무시**되므로 전체 건수가

| 먹는다 | 무시된다 |
|---|---|
| `lctnSdnm` (시도명) | `sidoNm` · `SIDO` · `addr` |
| `pbctStatCd` (입찰상태) | `cltrUsgLclsCtgrId` · `cltrBidBgngDt` · `bidBgngDt` |

### 같은 물건이 입찰 회차마다 한 행씩 나온다

대구권 **7,216행이 실제로는 1,899개 물건**이다. `onbidCltrno` 로 접되
아무 회차나 남기면 안 된다 — 진행중 회차를 우선하고, 그다음 입찰 종료일이
늦은 것을 남긴다(`better()`).

### 날짜 sentinel

입찰일이 없는 물건은 `299912301000` 으로 온다. 날짜로 쓰면 안 된다.

확인하지 못했다. `OnbidMvblListSrvc2` 등 9가지 이름을 넣어 봤으나 전부

```
printf '%s' "$KEY" | scripts/put_secret.sh datagokr
  → 거부: 이미 다른 값이 있습니다. 기존 지문 ... · 새 값 지문 ...
    서비스별로 파일을 나누십시오 (예: ~/.secrets/datagokr-bld)
```

**data.go.kr 인증키는 계정마다 다르고 서비스별 활용신청이 따로다.**
새 키를 받았다고 기존 자리에 쓰면 다른 서비스가 죽는다. 파일을 나눠라.

## 나이스옥션 대량 발굴 (2026-08-28)

**지역을 묶으면 안 된다.** `대구 달성군 중구 남구 서구` 로 한 번에 넣었더니

### 진행상태가 없다 — 이게 가장 중요하다

나이스옥션 스니펫에는 **`진행중` 같은 상태 표시가 없다.**

그래서 **`st:'미확인'`** 이라는 값을 새로 뒀다.

- 경매검색 상태 필터에 `상태 미확인` 항목을 추가했다.
- 카드에 회색 `상태 미확인` 배지와 경고문을 단다.

  법원 원본 대조가 필요합니다."
- 기본 필터(`진행중`)에는 안 잡힌다. 진행중이라고 주장할 근거가 없기 때문이다.
- **CODEF 큐 맨 앞에 세운다.** 진행중인지조차 모르는 물건이라 우선순위가 가장 높다.

### 감정가 0원 = 미지정

신건이라 아직 감정평가가 안 끝난 사건은 `감정가: 0원 | 최저가: 0원 | 용도: 미지정`
으로 온다. 0 을 금액으로 넣지 말고 `null` 로 두고 `감정가 미색인` 이라고 적는다.
용도도 비워 둔다 — `classify()` 에 넘기면 아파트로 추정해버린다.

## 블로그컨텐츠 — 아파트 전용화와 '권리분석 완료' 표시 (2026-08-28)

### 왜 아파트만 남기나

블로그컨텐츠 탭에 결격 없는 물건이 쌓이자 구성이 이렇게 나왔다.

| 출처 | 통과 | 내역 |
|---|---:|---|
| 공매 | 313 | 토지 191 · 상가 56 · **아파트 38** · 기타 28 |
| 법원경매 | 33 | **아파트 18** · 그 외 15 |

토지·상가가 압도적이라 아파트가 묻힌다.
권리분석 콘텐츠는 아파트만 다루므로 **용도 세그먼트를 넣고 기본값을 `아파트`** 로 뒀다.

```js
const BLOG = { lead: 14, src: '전체', use: '아파트' };
const isApt = x => isGm(x) ? x.scls === '아파트' : x.ut === '아파트';
```

법원경매는 `ut`, 공매는 `scls` 로 용도 필드가 다르다. 한쪽만 보면 절반이 샌다.

**오피스텔·주상복합·다세대는 뺀다.** 이름이 아파트처럼 보여도 권리관계와
시세 비교 방식이 달라서 같은 틀로 쓸 수 없다. 화면에도 그 이유를 적어 둔다.

### 40건 상한은 남긴다

공매가 들어오면서 통과 건수가 300을 넘겼다. 이 탭은 **소재 목록이지 목록 덤프가 아니다.**
`BLOG_CAP = 40` 을 유지하고 넘치면 "40건 표시" 를 눈에 보이게 적는다.

### 권리분석 완료 체크박스

작업한 물건을 지우지 않고 **흐리게** 만든다. 목록에서 사라지면 다시 찾기 어렵다.

```js
const BDONE_KEY = 'auction-board.blog.done.v1';
const BDONE = (() => {
  try { return new Set(JSON.parse(localStorage.getItem(BDONE_KEY) || '[]')); }
  catch (_) { return new Set(); }
})();
```

읽기·쓰기 **둘 다** try/catch 로 감싼다. 시크릿 창이나 사이트 데이터 차단 설정에서는
`localStorage` 접근 자체가 던진다 — 값이 비는 게 아니라 예외다.

세 가지 함정을 밟았다.

1. **체크하면 다시 그리고 싶어진다.** 그러면 보던 자리를 잃는다.
   클래스와 통계 숫자만 손보고 재렌더링은 하지 않는다.
   ```js
   c.closest('.bcard')?.classList.toggle('bdone', c.checked);
   ```
2. **카드 전체를 흐리게 하면 체크박스도 흐려진다.** 해제하러 갈 수가 없다.
   체크박스는 `opacity` 대상에서 빼고 초록으로 표시한다.
3. **`:hover`/`:focus-within` 에서 불투명도를 되돌린다.** 흐린 카드도 읽을 수는 있어야 한다.

```css
.bcard.bdone{opacity:.42}
.bcard.bdone:hover,.bcard.bdone:focus-within{opacity:1}
```

### 이 표시는 동기화되지 않는다

`localStorage` 는 **아티팩트 오리진별·브라우저별**이다. 재배포해도 남지만,
다른 기기·다른 브라우저로는 넘어가지 않고 사이트 데이터를 지우면 사라진다.
서버에 남는 기록이 아니므로 통계 타일 밑에 "이 브라우저에만 저장됩니다" 를 적어 둔다.
여러 사람이 나눠 작업할 거라면 이 방식으로는 안 된다.

data.go.kr 이 **아니다.** 국토교통부가 따로 운영하는 포털이고 계정도 인증키도 별개다.

인증키를 받아도 아직 아무것도 못 부른다. **통계표마다 따로 신청하고

— "API키까지는 발급이 되었는데 6개 정도 API 신청했는데 그 이후 승인단계에서…".

### 엔드포인트는 추측할 수 없다

요청 URL 은 **신청 화면에서 통계표·양식·시계열을 고르면 생성된다.**
("선택한 통계표 및 양식 정보를 파라메터로 URL에 포함되며") 그래서 코드에 기본
엔드포인트를 박아둘 수가 없다. 후보 6개를 찔러봤고 전부 404였다:

```
/portal/openapi/service.do  /portal/openapi/openapi.do  /portal/openapi/apiData.do
/portal/openapi/getStatData.do  /openapi/service  /portal/openapi/api.do
```

신청 화면이 준 경로를 `molit_stat "<경로및쿼리>"` 에 그대로 넘기는 방식으로 뒀다.

### 이 API 로는 실거래가를 대체하지 못한다

**집계 통계만 준다.** 개발커뮤니티 56번 글에서 이용자가 "착공 자료는 통계 수치자료만
있는데 개별 리스트를 open api 로 받을 수 없냐" 고 물었고, 관리자 답은 "어떤 항목인지
알려주면 제공 가능 여부를 안내하겠다" 였다. 2024-11 이후 진전 없음.

경매 물건의 최저가를 **같은 단지 실거래가와 비교**하려면 건별 원자료가 필요하다.
그건 여전히 data.go.kr `RTMSDataSvcAptTrade` 뿐이다. 통계누리 키로는 구·동 단위
평균·거래량까지가 한계다 — 배경 설명에는 쓰지만 시세 비교에는 못 쓴다.

### 이 호스트는 연결 리셋이 잦다

`stat.molit.go.kr` 은 같은 URL 을 연속으로 던져도 절반쯤 `curl: (35) Recv failure`
가 난다. 프록시 문제가 아니다(`recentRelayFailures` 비어 있음). 재시도를 5~6회까지
잡아야 붙는다. 한 번 실패했다고 "차단됨" 으로 결론짓지 마라 — 실제로 그렇게
잘못 판단할 뻔했다.

### 인증키 스캐너를 값 기반으로 바꿨다

패턴을 손으로 적어두는 방식(`grep -E 'yZMG|7c6deba9|…'`)은 키가 늘 때마다 빠뜨린다.
`scripts/scan_secrets.sh` 는 `~/.secrets/` 의 **실제 값**을 읽어 저장소를 훑는다.
새 키를 저장하는 순간 자동으로 검사 대상이 된다.

함정 둘을 밟았다.

1. **시크릿 파일에는 끝 개행이 없다**(`printf '%s'` 로 쓰므로).
   `while read -r v` 는 마지막 줄을 그냥 흘린다. 그래서 값 5개 중 **1개만**
   검사하고도 "깨끗함" 을 찍었다. 읽기 전에 `echo` 로 개행을 붙여 고쳤다.
2. **일치한 줄을 그대로 출력하면 스캐너가 스스로 키를 흘린다.**
   `cut -d: -f1,2` 로 위치(파일:줄)만 찍는다.

일부러 키를 심어 두 경우를 모두 확인했다 — 탐지 1건·종료코드 1, 제거 후 깨끗함.

### 단지명으로 매칭하면 안 된다

경매 주소에는 단지명이 아예 없는 경우가 흔하다 —
`북구 태전동 608-5 4동 14층1402호`. 그래서 **(법정동, 지번)** 을 1차 키로 썼다.
실거래가 API 가 `umdNm` 과 `jibun` 을 주므로 주소에서 그대로 뽑아 맞출 수 있다.

여기서 세 번 막혔다.

**1) `umdNm` 에 읍·면이 붙어서 온다.** `다사읍 서재리`, `압량읍 신대리`.
경매 주소에는 `서재리` 만 적힌다. 마지막 토큰으로도 찾는 색인을 따로 만들었다.
이걸 놓쳐서 처음에 달성군·경산군 물건이 통째로 미매칭이었다.

**2) 도로명주소.** `수성구 용학로 303, 302동 15층 1509호 (지산동,지산타운)`.
지번이 없다. 그런데 **괄호 안에 법정동과 단지명이 같이 들어 있다** — 이걸 쓴다.

**3) 이름 접미어 규칙.** 한국 아파트 이름은 **앞에 지역이 붙고 뒤에 차수가 붙는다.**

| 표기 | 실거래가 쪽 이름 | 관계 | 판정 |
|---|---|---|---|
| 침산동삼정그린코아 | 삼정그린코아 | 접두어만 다름 | 같은 단지 ✔ |
| 대화타워펠리스2 | 대화타워펠리스 | **차수가 다름** | 다른 단지 ✘ |

그래서 실거래가 쪽 이름이 표기의 **접미어일 때만** 받아들인다.

접미어 규칙만으로는 부족했다. `태전3차우방타운` 이 `우방타운` 에 붙었다.
`우방타운` 같은 이름은 대구에 널려 있고, 그 구에 우연히 하나만 수집됐다는
이유로 붙으면 **엉뚱한 단지의 시세**를 보여주게 된다. 괄호에서 얻은
**법정동까지 같을 때만** 접미어 매칭을 허용하도록 조였다. 법정동을 모르면
이름이 완전히 같을 때만 붙인다.

적중률 변화: 54건 → 109건(느슨) → **91건**(조인 뒤). 55건을 얻고 18건을 도로 버렸다.
버린 쪽이 맞다. 틀린 시세는 없는 시세보다 나쁘다.

### '시세의 2%' 에 초록 딱지를 붙일 뻔했다

gap 분포를 보니 최저 2% 가 나왔다. 확인해 보니 유찰 8~12회에 감정가의 1~6%까지
내려온 물건들이었다.

```

2%  최저 0.16억 vs 시세 8.25억  범어월드메르디앙 (유찰 11회)
3%  최저 0.08억 vs 시세 2.80억  매호효성백년가약 (유찰 10회)
```

정상적인 아파트가 이렇게 내려오지 않는다. 아무도 안 받아 갔다는 뜻이고, 대개
지분매각·유치권·대항력 임차인 같은 이유가 따로 있다. 여기에 "시세의 2%,
아주 쌈" 이라는 초록 딱지를 붙이면 **정반대로 읽힌다.**

`rt <= 30 || f >= 4` 이면 `deep` 을 세우고, 칩을 주황으로 돌리고, 상자에
"이 비율은 그대로 읽으면 안 됩니다" 를 굵게 적는다. 39/131건이 여기 해당한다.

### 면적을 모르면 그렇게 적는다

물건 전용면적을 모르면 그 단지 최다 거래 평형으로 대신했다.
**그건 이 호수의 면적이 아니다.** 131건 중 51건이 그렇다.

새로 넣은 3칸짜리 표가 이 규칙을 물려받아 390px 화면에서 카드를 가로로 터뜨렸다.

## 발굴을 스크립트로 옮겼다 — `scripts/harvest_nice.py` (2026-08-28)

지금까지는 검색 결과를 손으로 TSV 로 옮겨 적었다. 금액을 옮기다 틀리는 게
제일 흔한 사고고, 매번 같은 판단을 다시 하게 된다. 파서로 옮겼다.

```
scripts/harvest_nice.py raw.tsv --merge
```

입력은 `제목<TAB>설명` 한 줄에 하나. **정규화하지 말고 검색 결과를 그대로
붙여넣는다.** `<b>` 태그도 그대로 둬도 된다.

### 색인 형태가 셋이고 담긴 정보가 다르다

| 형태 | 예 | 얻는 것 |
|---|---|---|
| A | `대구서부 2025타경32237[1] 아파트 · 대구광역시 …` + `감정가 482,000,000원` | 용도·감정가 |
| B | `대구서부지원 경매6계 … \| 소재지: … \| 감정가: … \| 최저가: … \| 용도: 아파트` | **가장 풍부** |
| C | `소재지 : … , 청구금액 : … , 경매개시일 : …` | 청구액·개시일 |

같은 사건이 여러 형태로 잡히므로 `(법원, 사건번호, 물건번호)` 로 합친다.
합칠 때 **더 긴 주소를 채택한다** — 덜 가려진 쪽이다.

### 정규식에서 세 번 걸렸다

1. **법원을 제목 맨 앞에서만 찾았다.** `^(대구서부|대구)\s` 로 잡으니
   `나이스옥션 법원경매 대구서부 …` 형태가 통째로 실패했다. 문자열 어디서든
   찾되 **서부를 먼저** 본다 — '대구' 는 '대구서부' 안에도 들어 있다.
2. **주소 패턴이 쉼표를 막고 있었다.** `[^|·,]` 로 썼더니
   `…해링턴플레이스, 105동` 에서 끊겨 매칭이 실패했다. 단지명 뒤 쉼표는
   아주 흔하다. 구분자는 `|` 와 `·` 뿐이다.
3. **제목은 잘려서 온다.** `… 월성 자이....` 의 말줄임표가 주소에 딸려왔다.
   끝에 매달린 가림표(`OOOOOO`)도 같이 떼낸다.

### 주상복합을 아파트로 잡을 뻔했다

아파트 단서를 이름 꼬리(`타운·시티·파크·자이…`)로 판정하는데,
`신성미소시티주상복합` 이 '시티' 로 걸렸다. 권리관계와 시세 비교 방식이 달라
블로그 대상이 아니다. `주상복합|오피스텔|도시형생활주택|근린|상가|빌라|연립|다세대`
를 **먼저** 쳐낸다.

### 우물에는 바닥이 있다

구별 검색 결과 총량이 이렇게 다르다.

| 구 | 총 결과 |
|---|---:|
| 중구 | 494 |
| 남구 | 455 |
| 달서구 | 442 |
| **서구** | **148** |

서구는 25건만 받았는데 이미 정부 PDF·KRX 공시·huggingface `vocab.txt` 로
무너져 있었다. 쓸 만한 물건이 **0건**이었다.
**결과가 무너지면 그 구는 끝난 것이다.** 더 파지 말고 다음 구로 넘어가라.

같은 검색어의 2페이지(`start=31`)는 1페이지와 **하나도 겹치지 않았다.**
아직 안 판 구가 아니라 **안 판 페이지**가 남아 있다는 뜻이다.

### 상세 화면이 "1명 중 8명" 이라고 적고 있었다

```
임차인·전세권자가 최대 1명 당사자로 올라 있고, 그중 8명이 배당요구를 했습니다.
```

**두 숫자의 출처가 다르다.** `tenants` 는 당사자 목록(`parties`)에서 세고,
`claimedN` 은 문건접수내역(`docs`)에서 센다. **배당요구는 임차인이 아닌
채권자도 낸다.** 부분집합이 아닌데 '그중 M명' 이라고 쓰고 있었다.

`claimedN > tenants` 이면 문장을 바꿔 두 목록이 대응되지 않는다고 밝힌다.
`tenants > claimedN` 인 경우(인수 위험 신호)에만 부분집합 표현을 쓴다.

### 또 UTC 함정 — 이번엔 검증일

`datetime.date.today()` 는 컨테이너 시계(UTC)를 본다. 루틴이 **08시 KST = 전날
23시 UTC** 에 도니 `verifiedAt` 이 하루 전으로 찍혔다. 그래서 "오늘 새로 종료된
건" 이 0으로 집계됐다 — 실제로는 59건이었다.

CODEF 일일 카운터에서 이미 같은 함정을 밟고 `_codef_today()` 로 고쳤는데,
새로 쓴 코드에서 되풀이했다. **이 저장소에서 날짜를 찍을 때는 항상 KST 기준이다.**
`scripts/apply_codef.py` 에 못 박아 뒀다.

### `scripts/apply_codef.py`

CODEF 응답 묶음을 보드에 반영하고 원본을 보관하는 단계를 스크립트로 뺐다.
CODEF 가 주지 않는 `br`(건축물대장)·`mk`(시세)·`ar` 는 남기고 나머지는 덮는다.
돌린 뒤 `mask_names.py` 와 `attach_rtms.py` 를 반드시 이어서 돌려야 한다 —
보관본에는 매각물건명세서 비고의 실명이 그대로 있고, 용도가 바뀌면 시세 매칭도 달라진다.

## 권리분석 완료 표시가 통째로 날아갔다 (2026-08-29)

사용자가 체크해 둔 표시가 전부 풀렸다. **내가 틀렸다** — 8월 28일에
"재배포해도 남습니다" 라고 적었는데 남지 않았다.

먼저 원인을 좁혔다. 키 형식(`ct-{사건번호}-{물건번호}`, `gm-{id}`)은 그대로였고
저장 키 이름도 그대로였다. 즉 **저장소 자체가 비워진 것**이다.
오늘 하루에만 아티팩트를 네 번 재배포했다.

### 아티팩트 `artifact` 능력은 이 페이지에 안 맞는다

서버에 남기는 유일한 수단은 `artifact.publish(html)` 인데, **문서 전체를
다시 발행하고 열려 있는 모든 화면이 새로고침된다.** 이 페이지는 1.75MB 다.
체크박스 하나 누를 때마다 그걸 하는 건 말이 안 된다.
게다가 페이지가 스스로를 재생성하려면 자기 소스를 들고 있어야 하는데,
`outerHTML` 로 뜨는 건 금지돼 있고(런타임 변경이 섞인다) 소스를 통째로
심으면 파일이 두 배가 된다.

### 두 겹으로 나눴다

| 층 | 저장 위치 | 넘기는 것 |
|---|---|---|
| `BDONE_SEED` | `data/bdone.json` → 빌드가 박음 | 재배포·기기 변경·사이트 데이터 삭제 |
| localStorage | 브라우저 | 즉시 반영, 다음 굽기 전까지 |

화면에 보이는 값은 **시드 + 추가분 − 제외분**이다.

**해제도 기록해야 한다.** 구워진 값을 지우려면 "뺐다"는 사실이 남아야 하므로
추가분(`add`)과 제외분(`del`)을 따로 저장한다. 단순히 집합 하나만 저장하면
시드에 있는 항목은 해제해도 새로고침 때 되살아난다.

'표시 내보내기' 단추로 현재 목록을 복사해 대화에 붙여넣으면
`data/bdone.json` 에 구워 넣는다. 그 뒤로는 무엇을 해도 남는다.

네 경우를 실제로 돌려 확인했다 — 체크→저장, 새로고침 후 유지,
**저장소를 통째로 날려도 시드는 남음**, 시드 항목 해제가 유지됨.

### 빌드 순서 함정

`__BDONE__` 은 `site-pages.js` 안에 있는데 빌드가 데이터 치환을 먼저 하고
`__PAGES__` 를 나중에 끼우고 있었다. 그대로 두면 `__BDONE__` 이 영영 치환되지
않는다. **페이지 렌더러를 먼저 끼우고 데이터를 나중에 치환하도록 순서를 바꿨다.**
미치환 자리표시자 검사가 있어서 조용히 넘어가지는 않았다.

## 블로그컨텐츠에 지역 세그먼트를 넣었다 — 대구가 경북에 묻히고 있었다 (2026-08-31)

## 탱크옥션 상세정보 PDF — 못 보던 권리관계가 들어왔다 (2026-08-31)

사용자가 경매 상세정보 PDF 14건을 올렸다. 열어 보니 **지금까지 보드가
"확인할 수 없다" 고 적어온 것들**이 그대로 있었다.

- 등기부 갑구·을구의 권리 순서와 **말소기준등기**(날짜·권리자·채권최고액)
- 임차인의 **전입일·확정일자·배당요구·대항력 분석**
- 체납 관리비, 공시가격 6년치, 단지정보, 건축물 전유/공용 내역
- 매각사례, 국토부 실거래가

`pdftotext -layout` 으로 뽑으면 표 정렬이 유지돼 파싱이 된다.
`scripts/parse_tank.py` 로 뺐다.

### 실명은 파싱 단계에서 가린다

소유자·채무자·임차인 이름이 그대로 들어 있다. **저장한 뒤에 가리면 늦다** —
원본이 어딘가에 남는다. `parse()` 안에서 곧바로 가린다.
임차인 이름은 아예 저장하지 않고 전입·확정·배당·보증금·대항력만 남긴다.
법인·기관(신협·은행·공사…)은 가리지 않는다.

### 정규식이 두 번 틀렸다

1. **`소유자\s+(\S+)` 가 메모의 '전소유자 문제없고' 를 물어왔다.**
   소유자 이름이 `문OOO` 로 저장됐다. 표의 같은 줄에서 다음 칸 이름까지
   확인하도록 고쳤다 — `소유자\s+(\S+)\s+감정가`.
2. **기일 사다리의 결과 칸을 `\S*` 로 열어두니 다음 행의 'N차' 를 물어왔다.**
   2차 결과가 '매각결정기일' 로 잡히고 5차가 통째로 사라졌다.
   결과는 정해진 낱말뿐이므로 목록으로 못 박고 줄 끝을 앵커로 걸었다.
   매각불허가결정은 별도 줄이라 `decisions` 로 따로 받는다.

둘 다 **원문과 눈으로 대조해서** 찾았다. 파서가 값을 내놓는다고 맞는 게 아니다.

### 화면이 자기모순이었다

권리관계를 새로 보여주면서, 바로 아래 '확인 불가' 고지는 여전히
**"등기부 갑구·을구 권리관계는 이 화면에 없습니다"** 라고 적고 있었다.
탱크 출처가 있는 물건은 문구를 바꾼다 — 있는 건 있다고 하고, 대신
**상용 사이트가 정리한 값이라 가압류·가처분 전부가 담겼다는 보장은 없다**는
한계를 명시한다.

검증 배지도 갈랐다. CODEF 는 `법원 확인`, 이쪽은 `탱크옥션 상세정보`.
출처가 다른데 같은 배지를 달면 그것도 거짓말이다.

본문 첫 줄의 작은 용도 칩으로 대체했다. 훑을 때 먼저 읽어야 하는 건
용도가 아니라 진행 상태다.

**2) 늘 비어 있는 상자 두 개.** `전용면적 —` `최근 실거래 —` 가 값 없이도
항상 그려졌다. 모르는 걸 칸으로 보여줄 이유가 없다. 값이 있는 것만 그리고,
하나뿐이면 폭을 다 쓴다.

**3) 모든 카드에 붙는 `진행` 배지.** 263건 중 263건에 붙었다.
전부에 같은 배지를 다는 건 정보가 아니라 잡음이다. 기본 상태는 색 띠가
나타내고, 배지는 예외(매각·종료·미확인)에만 단다.

**4) 313px 짜리 마케팅 히어로.** 혼자 쓰는 도구에 "법원 원본으로
확인합니다" 를 크게 걸어둘 이유가 없다. 검색창 + 숫자 4칸으로 바꿔 165px.

**5) 90px 짜리 출처 고지.** 늘 펼쳐져 있으니 아무도 안 읽는다.
핵심 한 줄만 남기고 나머지는 `<details>` 로 접었다.

결과: 카드 높이 348 → 238px, 히어로 313 → 165px, 고지 90 → 69px.
첫 화면에서 물건이 보이기 시작한다.

### `<p>` 안에 `<details>` 를 넣으면 안 된다

접기를 넣자 모바일에서 문구가 **한 줄에 한 글자씩** 섰다.
`.notice` 는 `display:flex` 인데, `<p>` 안의 `<details>` 를 브라우저가
**`<p>` 를 강제로 닫으면서** 밖으로 빼낸다. 그래서 flex 아이템이 셋이 되고
`<p>` 가 짜부라졌다.

이 저장소에 이미 "`.notice` 는 flex 라 본문을 `<p>` 로 감싸야 한다" 고
적어뒀는데 그걸 내가 다시 밟았다. 이제 `<div class="nbody">` 로 본문 전체를
묶는다 — `<p>` 하나로는 부족하다. **flow content 를 넣을 거면 div 로 감싸라.**
