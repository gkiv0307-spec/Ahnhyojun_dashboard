**2단계 - 🕵️ 정보검수 직원** (job key `blogFactCheck`): 아이디어마다 핵심 통계·사실관계가 출처 URL의 실제 내용과 일치하는지 WebFetch나 재검색으로 원문을 직접 대조한다. 일치하면 다음 단계로 넘긴다. 확인이 안 되거나 의심스러우면 그 아이디어는 여기서 멈추고 5단계(보류)로 보낸다. 출처 URL·언론사·원문 문장은 memo·stageLog 에만 남기고, 작성 단계에 "본문에는 1차 출처(지지옥션·사법연감·한국부동산원·국토부·대법원 판결 등)만 쓰고 언론사·기사·전문가 인용은 우리 문장으로 바꿀 것" 을 메모한다.

**3단계 - ✍️ 작성 직원** (job key `blogWrite`): 정보검수를 통과한 아이디어만 본문을 작성한다. **제목은 학원 홍보 키워드 `<지역>경매학원` 으로 시작한다 (2026-10-02 대리님 지시)** — 지역은 **대구의 시·군·구·동·읍·면을 매번 골고루 섞어** 고르고 한 키워드로 고정하지 않는다. 후보: 시 `대구경매학원` / 구·군 `중구·동구·서구·남구·북구·수성구·달서구·달성군·군위군` / 동·읍·면 예시 수성구 범어동·만촌동·황금동·지산동·시지동·두산동·상동·중동·파동, 달서구 상인동·월성동·용산동·죽전동·본리동·대곡동·진천동·유천동·이곡동·감삼동, 북구 칠곡·구암동·태전동·동천동·침산동·복현동·산격동·대현동, 동구 신천동·율하동·신서동·각산동·효목동·방촌동, 서구 평리동·내당동·비산동, 남구 대명동·봉덕동, 중구 삼덕동·대신동·남산동, 달성군 화원읍·다사읍·옥포읍·논공읍·현풍읍·유가읍·가창면·하빈면·구지면, 군위군 군위읍(이 밖의 대구 동·읍·면도 된다) → `범어동경매학원`·`화원읍경매학원` 처럼 붙여 쓴다. 고르는 순서: ① 글에 대구 안 지역이 나오면 그 지역. ② 아니면 스냅샷의 최근 파이프라인 글(blogauto-… id) 10건 제목에 쓰인 지역을 피해 시 → 구·군 → 동·읍·면 급을 번갈아 돌린다(같은 지역을 10건 안에 두 번 쓰지 않는다). 같은 키워드를 메타디스크립션 줄·본문 첫 문단("안녕하세요, 범어동경매학원 옆커폰부동산에듀입니다." 식)·해시태그(그 키워드 + `#대구경매학원`)에 각 1회 넣고, 항목의 `mainKeyword` 필드에 그 키워드를 적는다(대시보드 순위 확인이 이 키워드로 잰다).

**4단계 - 📐 SEO검수·발행 직원** (job key `blogSeo`): **제목 45자 이하**(홍보 키워드를 포함한 전체 글자 수를 직접 셀 것), **제목이 `<지역>경매학원` 으로 시작하고 그 지역이 최근 파이프라인 글 10건에 안 쓰인 것인지, 같은 키워드가 메타디스크립션·첫 문단·해시태그에 있는지, `mainKeyword` 가 채워졌는지**, **뉴스 발췌 흔적이 없는지(본문·메타디스크립션에 "기사·보도·발췌·원문·~라고 전합니다", 언론사·기자 이름, 따옴표 직접 인용이 하나도 없는지 문자열로 직접 찾는다 — 1차 출처 기관 이름은 허용)**, 핵심 키워드가 제목과 첫 문단에 있는지, 메타디스크립션 줄이 리터럴로 있는지, 질문형 소제목·핵심정리·FAQ·해시태그 5개 이상, 1,500자 이상, 금지 표현 없음을 전부 확인한다. 금지 표현은 **단어가 아니라 단정하는 문장**을 말한다 — "무조건 안전한 건 아닙니다" 같은 부정·반문은 통과시킨다. 충족하면 "발행대기"로 올린다. 미달이면 어떤 항목이 왜 미달인지 구체적으로 적어 5단계로 넘긴다.

**5단계 - 🧑‍⚖️ 최종검토 직원** (job key `blogApprove`): 걸러진 항목은 "보류"로 확정하고 구체적인 사유(holdReason)를 남긴다. "발행대기"까지 온 항목은 승인 메모만 남긴다.

**결과 취합**: 오늘 처리한 모든 아이디어(보류 포함)를 다음 형태의 객체 배열로 만든다. 각 항목은 거쳐간 단계마다 stageLog에 기록을 남긴다:
{ id(고유 문자열), date(오늘), title(`<지역>경매학원` 으로 시작), mainKeyword(홍보 키워드), topic, status("아이디어"|"정보검수중"|"작성중"|"SEO검수중"|"발행대기"|"보류" 중 실제 멈춘 단계), url:"", memo(요약+출처 URL — 내부용), body(3단계까지 갔다면 본문, 아니면 ""), createdAt(ISO), stageLog:[{stage, by, at, note}...], holdReason(보류인 경우만) }

이 배열을 { runAt(지금 ISO), status:"success"|"no_new"|"error", addedCount(배열 길이), note(사유 요약, 정상이면 빈 문자열), items:[…] } 로 감싸서 title "ahj_blog_chunk_YYYY-MM-DD.json"(오늘 날짜, parentId 위와 같음, contentMimeType "application/json", disableConversionToGoogleType true)으로 업로드한다.

**6단계 - 근무 기록 남기기 (반드시 마지막에, 0건으로 끝나도 한다)**

오늘 실제로 수행한 단계마다 아래 객체를 만들어 **하나의 배열**로 묶고, title "ahj_patch_chunk_YYYY-MM-DD_routine_blog.json"(오늘 날짜, 같은 폴더, contentMimeType "application/json", disableConversionToGoogleType true)으로 업로드한다. 0단계에서 멈췼으면 `blogPipeline` 하나만 status:"hold"로 남긴다.

{"op":"push","list":"routineRuns","fields":{
  "id":"rr-YYYYMMDD-<jobkey>", "job":"<blogPipeline|blogFactCheck|blogWrite|blogSeo|blogApprove>",
