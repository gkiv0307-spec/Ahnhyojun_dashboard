# 한국 부동산 뉴스 브리핑

경제지 웹사이트와 네이버 뉴스를 **병렬 서브에이전트**로 동시에 훑어서, 한쪽만 볼 때보다 빠르고 교차 검증된 부동산 뉴스 브리핑을 만드는 스킬이다. 두 출처는 성격이 달라서 같이 보는 게 유용하다: 경제지(한국경제·매일경제 등)는 심층 기사와 정책 배경 설명이 풍부하고, 네이버 뉴스 검색은 여러 매체를 가로질러 최신순으로 빠르게 훑을 수 있어 그날그날의 속보성 이슈를 놓치지 않게 해준다.

## 언제 쓰는가

사용자가 부동산 시장 조사, 오늘의 부동산 뉴스, 집값/전세값 동향, 부동산 정책 브리핑 등을 요청할 때 이 스킬을 사용한다. "네이버 부동산에서 매물 시세를 가져와줘" 같은 실거래가/매물 조회 요청은 이 스킬의 범위가 아니다 (land.naver.com 등 네이버 부동산 매물 사이트는 브라우저 안전 정책상 접속이 차단되어 있으므로, 시세 조회가 목적이면 사용자에게 직접 확인을 안내하거나 다른 방법을 찾는다). 이 스킬은 어디까지나 **뉴스 기사** 수집·요약용이다.

## 워크플로우

### 1단계: 작업 계획 수립

TaskCreate로 최소 3개의 작업을 만든다: (1) 경제지 사이트 조사, (2) 네이버 뉴스 조사, (3) 통합 브리핑 작성. 두 조사 작업은 서로 의존하지 않으므로 병렬로 처리한다.

### 2단계: 두 서브에이전트를 같은 메시지에서 동시에 실행

Agent 도구를 **한 번의 메시지에서 두 번 호출**한다(순차 호출 금지 — 병렬로 띄워야 시간이 절약된다). 최종 산출물이 "제목 + 링크" 리스트이므로, 각 서브에이전트에게는 기사를 깊이 요약하기보다 **좋은 기사를 고르고 정확한 링크를 확보하는 데** 집중하라고 지시한다.

**서브에이전트 A — 경제지 웹 조사 (subagent_type: general-purpose, Claude in Chrome 도구 사용)**

프롬프트 예시:
```
Claude in Chrome 도구로 한국경제(hankyung.com/realestate) 부동산 섹션과 매일경제 등 경제지 사이트에 접속해서
[오늘 날짜] 기준 부동산 시장 관련 최신 기사 5~8개를 조사해줘.
각 기사마다 (1) 정확한 기사 제목, (2) 기사 URL, (3) 한 줄 요약(선택)을 정리해서 보고해줘.
정책/공급대책, 세제, 가격·거래 동향, 청약 등 주제가 겹치지 않게 대표성 있는 기사를 골라라.
주의: land.naver.com, new.land.naver.com, fin.land.naver.com, n.news.naver.com 등
네이버(naver.com) 도메인은 브라우저 안전 정책상 접속이 차단되어 있으니 시도하지 말 것.
언론사 원문 도메인(hankyung.com, mk.co.kr, ytn.co.kr, chosun.com 등)은 접속 가능.
tabs_context_mcp로 탭을 먼저 확보하고, get_page_text로 기사 본문을 읽어라.
```

**서브에이전트 B — 네이버 뉴스 검색 (subagent_type: general-purpose, Naver MCP 도구 사용)**

프롬프트 예시:
```
Naver 검색 MCP의 NaverSearch-search_news 도구로 "부동산", "부동산 시장 전망", "주택 공급대책" 등의
키워드를 sort=date로 검색해서 [오늘 날짜] 기준 가장 최신이고 핵심적인 부동산 뉴스를 찾아줘.
검색 결과 중 중요도가 높은 기사(정책 발표, 가격 동향, 대통령/정부 발언, 세제, 공급대책, 재건축·정비사업 등)를
8~10개 골라라. 각 기사마다 (1) 정확한 기사 제목, (2) link 필드(n.news.naver.com 링크. 없으면 originallink),
(3) 한 줄 요약(선택)을 정리해서 보고해줘.
link/originallink는 검색 API가 반환한 URL 문자열을 그대로 인용하면 되고, 브라우저로 열어서 확인할 필요는 없다
(naver.com 도메인은 브라우저 접속이 차단되지만, 링크 텍스트 자체를 결과에 포함하는 것은 문제 없다).
기사 본문을 더 확인하고 싶으면 originallink가 naver.com이 아닌 언론사 자체 도메인일 때만 접속해라.
```

### 3단계: 결과 통합

두 서브에이전트가 모두 끝나면 결과를 하나의 리스트로 합친다. 같은 기사가 양쪽에서 겹치면 하나만 남긴다. 중요도·시의성이 높은 기사(정책 발표, 공급대책, 세제, 가격 동향 등)를 우선 배치하고, 총 8~12개 정도로 추린다.

### 4단계: 출력 형식

기본 출력 형식은 **날짜 헤더 + "제목 / 링크" 리스트**다. 사용자가 이 형식을 명시적으로 선호한다고 확인했으므로, 별다른 지시가 없으면 항상 이 형식을 쓴다. 정확히 아래 템플릿을 따른다 (요일은 실제 요일로, 날짜는 실제 오늘 날짜로):

```
[YY년 M월 D일 요일] 부동산 주요뉴스

기사 제목 1
https://실제-링크-1

기사 제목 2
https://실제-링크-2

...
```

- 제목은 검색/조사로 확인한 실제 기사 제목을 쓴다 (지어내지 않는다). 필요하면 핵심 키워드가 드러나도록 살짝 다듬어도 되지만 사실을 바꾸지 않는다.
- 링크는 실제로 확인된 URL만 쓴다. 네이버 뉴스 링크(n.news.naver.com)가 있으면 우선 쓰고, 없으면 언론사 원문 링크를 쓴다. 링크를 확인하지 못한 기사는 목록에서 뺀다.
- 기사 본문을 그대로 길게 베끼지 않는다. 제목에 담긴 정보 이상으로 부연설명이 필요하면 제목 뒤에 괄호로 짧게만 덧붙인다.
- 사용자가 "요약해서", "설명 곁들여서" 등 프로즈 형태를 원한다고 명시하면 그때는 문단 요약 형식으로 전환한다 (이 스킬의 예전 기본값). 기본값은 링크 리스트다.

## 주의사항

- **네이버 부동산/뉴스 도메인 직접 접속 금지**: land.naver.com, new.land.naver.com, fin.land.naver.com, n.news.naver.com 등은 Claude in Chrome에서 안전 정책상 차단된다. 매물 시세가 필요하면 사용자에게 직접 확인을 권하고, 뉴스는 NaverSearch MCP 도구(뉴스 검색 API)로 대체한다.
- 언론사 홈 URL이 바뀌었거나 404가 뜨면(예: mk.co.kr/realestate/ 같은 옛 경로) 검색 결과에서 얻은 개별 기사 원문 링크로 바로 접속하는 방식으로 우회한다.
- 서브에이전트 중 하나가 실패하거나 관련 MCP가 연결되어 있지 않으면, 나머지 한쪽 결과만으로 브리핑을 작성하고 어느 출처가 빠졌는지 사용자에게 알린다.
- 저작권 보호를 위해 기사 본문을 대량으로 그대로 인용하지 않는다.
